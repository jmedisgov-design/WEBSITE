Product

Scenarios, not one-off answers

A policy question is rarely settled by a single number. The scenario builder lets an analyst vary a shock, run it, save it, clone it, compare it against the baseline and against a colleague’s scenario, and download the comparison.

Scenario builder

Sixteen shock families

Shocks are entered in the units a ministry uses, converted by the platform, and recorded in the run provenance exactly as entered.

Fiscal

Government expenditure

By vote, programme or sector, with a phasing profile across the framework period.

Scenario operations

What an analyst can do with a scenario

  • Create from a template, a registered question or a blank sheet
  • Clone an existing scenario and vary one shock
  • Run through the job queue, without blocking the interface
  • Compare two or more scenarios against each other and the baseline
  • Save into a project, with the full parameter set
  • Share with named colleagues inside the organisation
  • Download results as Excel, CSV, Word, PDF, charts and maps

Execution

The run queue

A scenario is submitted, not executed inline. The queue gives every run an identifier, a state and a place in the result store, so nothing is lost when a browser is closed.

Run request → Job queue → Model worker → Status → Result store → Interface update

Failure is reported, not smoothed

If a model does not converge, EDIS says so and shows the diagnostics. It does not fall back to a language model, an extrapolation or a previous run.
